# Virtual buffering for pharmaceutical refrigeration

This repository contains the analysis used to develop and evaluate two long short-term memory (LSTM) estimators of a glycol-buffered temperature reference, $T_{\mathrm{P1}}$. One estimator uses the refrigerator's temperature report acquired through Bluetooth Low Energy (BLE); the other uses air temperature measured by a centrally positioned BME280 sensor. The analyses cover model development, an independent holdout evaluation, and a separately collected prospective operational challenge.

## Repository contents

| Path | Contents |
|---|---|
| `data/` | The three aligned, one-minute datasets in the Excel format read by the notebook and in open CSV format. |
| `notebooks/virtual_buffering_analysis.ipynb` | Complete model development, reference-estimator comparison, evaluation, and figure/table generation. |
| `outputs/models/` | Selected trained estimators, scalers, and LSTM training histories. |
| `outputs/publication/` | Prediction exports, numbered table data, and manuscript and supplementary figures generated by the notebook. |
| `scripts/` | A file-inventory generator and an optional cleanup utility for machine-specific paths in saved notebook displays. |

The three datasets contain 310,225 aligned observations in total: 280,571 for model development, 26,810 for independent holdout evaluation, and 2,844 for prospective evaluation. Their five source columns and dataset roles are documented in [`data/README.md`](data/README.md). These are analysis-ready datasets; original device acquisition logs are not included.

## Reproduce the analysis

Use Python 3.12.13 and the packages listed in [`requirements.txt`](requirements.txt). The versions of Python, NumPy, pandas, scikit-learn, TensorFlow, and Keras recorded for the completed analysis are pinned there; exact versions of the remaining plotting and utility packages were not recorded.

1. Keep the repository folder structure intact and install the dependencies in a fresh Python environment.
2. Open `notebooks/virtual_buffering_analysis.ipynb` from within this repository and run all cells in order. The notebook finds `data/` and writes its results under `outputs/`.
3. Compare regenerated publication files with `outputs/publication/`. The notebook trains both LSTMs and the reference estimators; the saved models are provided for inspection and reuse, but are not required as inputs to a full rerun.

The analysis uses a fixed random seed and requests deterministic TensorFlow operations. Small numerical differences can still occur across hardware or software environments. Predictions begin only after the pathway-specific input history is complete: 120 minutes for the refrigerator-reported input and 60 minutes for the BME280 input.

The notebook also creates detailed intermediate files in `outputs/run_artifacts/`; these can be regenerated and are not part of the versioned repository. After a rerun, `python scripts/sanitize_notebook_outputs.py` removes machine-specific paths from saved notebook displays without changing code, figures, or numerical results.

## Scope and provenance

The refrigerator setpoint column describes experimental conditions; it is not a model input. The buffered reference is the calibrated glycol-probe measurement, not a direct measurement of an individual stored product. The two evaluation datasets were kept separate from model fitting and selection.

Acquisition firmware and reconstructed development sketches are not required to rerun this analysis and are not included here while their exact provenance and redistribution rights are resolved. The manuscript's supplementary material contains the calibration documentation and experimental schedules; it is supplied with the article rather than duplicated in this repository.

The article citation and an archival DOI for this repository will be added when available.
